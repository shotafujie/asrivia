# 仕様: 辞書の「読み」で認識結果を置き換える

## 背景

qwen の context は「ヒント」にすぎず、英語の登録語がカタカナで認識される(例: `Claude` →「クロード」)
場合を直せなかった(実機と `benchmarks/qwen-context/` の両方で観測)。
辞書の登録語に任意の「読み」を持たせ、認識結果に読みが現れたら登録語へ置き換える。
context(ヒント)と併用し、置換は確実に効く後処理として働く。

置換後のテキストが、字幕の表示・翻訳・koepus の仮説テキストのすべてに使われる
(利用者が目にして直す対象と、コーパスに残る仮説を揃えるため)。

## 仕様

- **SPEC-016** 読みを持つ登録語があるとき、認識結果に現れた読みを、すべて登録語に置き換える
- **SPEC-017** 読みは `,` / `、` / `，` 区切りで複数指定でき、前後の空白を除いた各読みが置換対象になる(空の読みは無視する)
- **SPEC-018** 読みどうしが重なる場合、長い読みを優先して置き換える(「クロードコード」「クロード」の両方が登録されていれば「クロードコード」を先に置き換える)
- **SPEC-019** 読みを持たない登録語しかないとき、認識結果は変わらない
- **SPEC-020** 読みは words.json の各項目の `reading` キーに保存され、読み込める。`reading` キーの無い既存の words.json は、全語が読みなしとして読める
- **SPEC-021** 生成後に words.json が更新された場合、次の置換から更新後の読みが使われる。words.json が JSON として読めない場合は例外を出さず、直前に読めた読みを使う(一度も読めていなければ置換しない)
- **SPEC-023** 読みはひらがな・カタカナを区別せずに照合する(ひらがなで登録した読みも、カタカナで現れた認識結果を置き換え、その逆も同様)。置換されない部分の文字は変えない
- **SPEC-022** 辞書ウィンドウの「読み（任意）」欄に入力して追加すると、その読みで登録され、追加後に読み欄は空になる
- **SPEC-025** 登録済みの語の編集ダイアログは、読み欄にその語の現在の読みを入れた状態で開く
- **SPEC-026** 編集ダイアログで「適用」すると、その語の読みと boost が入力値に更新されて words.json に保存され、メモは変わらない

## 範囲外(自動テストの対象外・手動確認)

- hf / qwen バックエンドで、置換後のテキストが字幕・翻訳・koepus に渡ること(`main.py` の認識ループ)
- 辞書ウィンドウの一覧に読みが表示されること
- 仮字幕(ライブ字幕)には置換を適用しない(確定時に置き換わる)
