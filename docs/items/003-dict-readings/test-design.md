# テスト設計: 辞書の「読み」で認識結果を置き換える

- 置換は `ReadingReplacer`(`asr/biasing/readings.py`)を一時 words.json で検証する(`tests/test_readings.py`)
- 保存形式は `WordRegistry`(`asr/biasing/registry.py`)を一時ファイルで検証する(`tests/test_readings.py`)
- 辞書ウィンドウは非表示の実 `tk.Tk` で `DictWindow` を検証する(`tests/test_dict_launcher.py`)

### SPEC-016 読みを持つ登録語があるとき、認識結果に現れた読みを、すべて登録語に置き換える

- **TC-016-1** `Claude`(読み クロード)→「クロードで実装した」が「Claudeで実装した」になる
- **TC-016-2** 同じ読みが2回現れる →「クロードとクロード」が「ClaudeとClaude」になる

### SPEC-017 読みは `,` / `、` / `，` 区切りで複数指定でき、前後の空白を除いた各読みが置換対象になる

- **TC-017-1** `JAIST`(読み「ジャイスト, ダイスト、ジェイスト，ジャイスド」)→ 4つの読みがそれぞれ JAIST になる
- **TC-017-2** 読み「クロード,,  」(空要素・空白)→「クロード」だけが置換され、空文字による置換で文が壊れない

### SPEC-018 読みどうしが重なる場合、長い読みを優先して置き換える

- **TC-018-1** `Claude`(クロード)を先、`Claude Code`(クロードコード)を後に登録 →「クロードコードで」が「Claude Codeで」になる

### SPEC-019 読みを持たない登録語しかないとき、認識結果は変わらない

- **TC-019-1** 読みなしの `Claude` のみ →「クロードで実装した」は変わらない
- **TC-019-2** registry_path の words.json が存在しない → 例外なく、入力がそのまま返る

### SPEC-020 読みは words.json の各項目の `reading` キーに保存され、読み込める。`reading` キーの無い既存の words.json は、全語が読みなしとして読める

- **TC-020-1** `add(word, reading=...)` で保存 → JSON の該当項目の `reading` が一致し、読み直した BiasWord の reading も一致
- **TC-020-2** `reading` キーの無い JSON を読む → 例外なく、各語の reading が空文字

### SPEC-021 生成後に words.json が更新された場合、次の置換から更新後の読みが使われる。読めない場合は直前の読みを使う

- **TC-021-1** 読みなしで生成 → 読みを追加して mtime を進める → 次の置換で読みが効く
- **TC-021-2** 読みありで置換 → 途中までの JSON に書き換えて mtime を進める → 例外なく、直前の読みで置換される
- **TC-021-3** 生成時点で words.json が壊れている → 例外なく、入力がそのまま返る

### SPEC-022 辞書ウィンドウの「読み（任意）」欄に入力して追加すると、その読みで登録され、追加後に読み欄は空になる

- **TC-022-1** 単語欄 `Claude`、読み欄「クロード」で追加 → registry の Claude の reading が「クロード」、読み欄が空

### SPEC-023 読みはひらがな・カタカナを区別せずに照合する。置換されない部分の文字は変えない

- **TC-023-1** 読み「くろーどこーど」(ひらがな)→「クロードコードで実装した」が「Claude Codeで実装した」になる
- **TC-023-2** 読み「クロード」(カタカナ)→「くろーどさん」が「Claudeさん」になる
- **TC-023-3** 読み「くろーど」→「クロードとくろーど、ひらがなのまま」で、置換対象外の「ひらがなのまま」は変わらない
