# 仕様: qwen バックエンドで辞書(words.json)を context として反映する

## 背景

辞書UI(words.json)は hf バックエンドでしか認識に効かなかった。qwen(Qwen3-ASR / MLX)は
日本語精度で優れるため、qwen を主軸にしたまま辞書を効かせたい。Qwen3-ASR の
`Session.transcribe(context=...)`(システムプロンプト)に登録語を渡す方式を採る。

効果(登録語の再現率・CER・レイテンシ)は性能仕様として `benchmarks/qwen-context/` で検証する。

## 仕様

- **SPEC-001** `registry_path` を指定しない場合、認識は context を空文字で呼ぶ
- **SPEC-002** words.json に登録された語は、すべて認識時の context に含まれる
- **SPEC-003** context は登録語を登録順に `", "` で連結した文字列であり、登録語が0語なら空文字である
- **SPEC-004** words.json が存在しない場合、認識は context を空文字で呼び、例外を出さない
- **SPEC-005** 生成後に words.json が更新された場合、次の認識から更新後の登録語が context に反映される
- SPEC-006(廃番 2026-09-29: SPEC-024 に置き換え。実機で無音・雑音の短い区間の漏れが多発し、再認識が認識時間を倍にしたため)
- **SPEC-024** context 付きの認識結果に含まれる、異なる登録語の数が3以上の場合(NFKC 正規化・大文字小文字を無視した部分文字列で照合)、認識し直さずに空文字の結果を返す(その区間を捨てる)
- **SPEC-007** context 付きの認識結果に含まれる、異なる登録語の数が2以下の場合(同じ語が何度出ても1と数える)、認識し直さずにその結果を返す
- **SPEC-008** words.json が JSON として読めない場合、認識は例外を出さず直前に読めた登録語の context を使い(一度も読めていなければ空文字)、読める状態に更新された後の認識から反映する

## 既知の制約(仕様として受け入れるもの)

- SPEC-024 の照合は部分文字列一致のため、短い登録語(例: `AI`)は別の語の一部(`MAIL`)にも一致する。
  また、登録語を正当に3語以上含む発話も漏れとみなされ、その区間は捨てられる。
  短い本物の発話(例: 登録語1語だけの相づち)が漏れた場合も捨てられる(実機では無音・雑音区間の漏れが大半だったため受け入れる)
- 登録語が2語以下の辞書では、漏れても SPEC-024 の条件を満たさず検出できない
- 更新の検出は words.json の mtime による。mtime が変わらない書き換えは検出しない

## 範囲外(自動テストの対象外)

- qwen バックエンド起動時に PiP の 📚 ボタンが表示されること(tkinter UI。手動確認)
- 効果の大きさ(`benchmarks/qwen-context/README.md` で基準比較)
